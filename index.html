Seis etapas. Uma leitura.

01 / 06

Sensor

(LT-101)

O sensor de nível mede o tanque físico, na bancada, e manda esse valor pro CLP — é a única etapa das seis que acontece fora de um computador.

PROCESSO

64.7 %

02 / 06

CLP

(DB1.PV)

O CLP (Controlador Lógico Programável) guarda essa leitura numa variável da própria memória — é onde o sinal analógico vira um número que o resto do sistema consegue usar.

PLCSIM

REAL := 64.7

03 / 06

Integração

(Node-RED)

O Node-RED lê essa variável do CLP e publica o valor pra fora da rede industrial — é a ponte entre o mundo da automação (CLP) e o mundo do software comum (APIs, bancos, telas).

NODE-RED

msg.payload = 64.7

04 / 06

API

(ASP.NET Core)

O backend recebe o dado do Node-RED e expõe como uma API — um endereço que qualquer aplicação pode consultar pra saber o valor atual.

{ "pv": 64.7 }

05 / 06

Banco de dados

(PostgreSQL)

Cada leitura recebida fica salva no banco de dados, com data e hora — é o que permite reconstruir o histórico depois, não só ver o valor de agora.

ESTRUTURA PREVISTA

leituras_nivel.pv = 64.7

06 / 06

Tela

(Web)

A interface web consulta esse histórico e desenha o gráfico — o último passo, transformar um número guardado no banco em algo que uma pessoa consegue olhar e entender. É a mesma leitura da LT-101, seis etapas atrás.

SOBRE O PROJETO

Por que simular uma malha de nível?

Automação industrial e desenvolvimento de software costumam ser tratados como mundos separados nos cursos técnicos — quem mexe com CLP não mexe com banco de dados, quem escreve backend não vê o processo físico do outro lado.

O SmartPLC fecha esse ponto cego: uma malha de nível de 1ª ordem, com controle P rodando num CLP simulado, lida pelo mesmo número até a tela, em seis camadas técnicas diferentes — dá pra ver exatamente onde cada uma entra e por quê.
